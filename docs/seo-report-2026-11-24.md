## 1. 原网站发现了哪些 SEO 问题

审计于 2026-11-16 在本地构建上进行，分七个方向：抓取配置、页面元数据、结构化数据、内部链接、内容与关键词、可信度与商业披露、性能。没有发现阻碍抓取或收录的 P0 问题：robots.txt、sitemap、canonical、真 404、服务端渲染正文在本地都正常，Bingbot 与普通浏览器拿到的页面逐字节相同。

主要问题（P1）：

- **首页与指令不符**：Title、H1、Description 都不是指定文案；指定的 9 个 H2 和 7 个排行 H3 一个都没有；推荐区只展示 3 个品牌，顺序（灵动云、飞V、暮光加速……）与指定顺序不同；站名仍是“机场选”。
- **品牌页太薄、太像模板**：18 个品牌页的 Title、Description、H2 骨架都由同一模板生成；H1 只有品牌名，英文名与中文名粘连（如“暮光加速Twilight”“FireflyFirefly”）；六个重点品牌页的原创叙述只有 88–158 个汉字；缺少使用需求分析、优势与限制、常见问题和发布 / 更新日期；页面上直接显示仓库内部文件路径。
- **结构化数据与页面不一致**：16 篇文章输出的 FAQPage（48 组问答）在页面上看不到；品牌页没有 BlogPosting；首页和品牌库没有 ItemList；文章用的是 Article / TechArticle 而不是 BlogPosting。
- **内部链接**：首页没有“排行榜 → 品牌页”模块；16 篇文章正文里一条手写内链都没有（25 处《文章名》是纯文本）；没有任何文章链接到六家重点品牌的资料页；18 个品牌页的“相关阅读”完全相同。
- **内容与关键词**：/recommend/ 与 /brands/ 两页正文几乎重复（6-gram 相似度 0.833），并与首页争“机场推荐”；Clash Meta 兼容、AI 工具、YouTube 4K / Netflix、多设备、IEPL / IPLC、低价套餐、流量倍率、晚高峰稳定性等关键词没有承接页；节点地区文章里“AI 工具先选香港或台湾”的建议与本站自己的检测结果冲突。
- **可信度与披露**：十余处“不打分、不排名”的表述会与新的“第一名……第七名”榜单矛盾；首页推荐区与 /recommend/ 区块内没有推广披露；没有推荐榜排序原则、没有更新记录；联系邮箱未设置、联系页直接显示环境变量名；作者介绍过薄。
- **抓取细节**：sitemap 的 lastmod 不随品牌与套餐数据更新，IndexNow 增量提交会因此漏掉页面；静态导出（Cloudflare Pages）路径没有用当前代码验证过；HTTPS 与 www 统一没有任何落地步骤。

次要问题（P2 / P3，节选）：

- IndexNow 脚本：`--urls` 模式会导致重复提交、删除或迁移的 URL 不会通知、网络错误和密钥验证失败不写日志。
- /compare/ 初始 HTML 只有 55 / 332 行套餐，加载完整数据后整表替换，桌面端 CLS 0.133；套餐筛选组件把 zod 与全部品牌、套餐数据打进 244 KB 的客户端脚本，22 个页面都加载它。
- 13 篇文章里推广卡片按钮的文字对比度只有 1.29:1；14 页 Title 按显示宽度偏长；标签页 noindex 同时 nofollow，成为爬虫死胡同；/search/ 既被 robots 禁止又带 noindex。
- 首页移动端首次排版有一个 265–347 ms 的长任务，Lighthouse 移动端性能分在 79–97 之间波动。

2026-11-24 的代码复核（运行时、SEO、事实、导出与抓取、界面无障碍与性能五个方向，每条问题再经第二人复核确认）另外发现：

- 抓取与结构化数据：列表页顶层结构化数据类型是指令名单之外的 CollectionPage；www 跳主域名会丢结尾斜杠、多跳一次；预览环境的 robots 禁止抓取，爬虫读不到 noindex。
- 事实与措辞：排行榜卡片对隐形人、飞猫云的地区数算错；12 个兜底品牌页标题把“东南亚”“欧美”这类统称算进地区数；若干处文字把品牌资料附带的文字记录算成本站测试；多处写“每份测试记录都注明网络环境与工具”，但 2026-11-10 的记录没写本地运营商与城市，2026-10-28 的文字记录没写工具；隐私页把读者引向目前还没有联系渠道的联系页。
- 界面与无障碍：延迟渲染样式让页内锚点跳转落点偏移、标题暂时不进无障碍树、卡片阴影被裁；深蓝渐变区域的键盘焦点框几乎看不见；收起的常见问题仍被读屏读出，而且每个答案都成为一个地标区域；资料档案区块的标签指向内层标题；首页概览的标签被读两遍。
- 手机与性能：首页低价对比按钮在 360px 宽度放不下；价格单位在手机上断行（“¥109 /”与“年”分两行）；套餐筛选组件的脚本仍被加载到所有栏目页和文章页。

## 2. 哪些问题已修复

**站名与首页**

- 全站改名为“机场优选”（Title 模板、Organization / WebSite、作者署名、披露文案、封面与分享图），英文名与网址不变。
- 首页 Title、Description、H1、副标题逐字使用指定文案；9 个 H2 按指定顺序排列；新增“2026 热门机场推荐排行榜”，7 个 H3 与指定顺序逐字一致，每项链接到品牌页，榜单上方的说明框写明“编辑推荐顺序，包含推广合作因素，不是测速或评分排名”，并输出同序的 ItemList。
- 新增七家套餐价格比较表（服务端渲染，按资料计算每 GB，标注价格状态与资料日期）、按需求选择、关于与更新说明模块；首页不再加载 55 行的筛选组件。
- 顺序固定在 `lib/ranking.ts`，`data/brands.json` 前七家的 featuredOrder 同步为 1–7，校验脚本会检查两者一致。

**七个品牌页**

- 七家各有一篇编辑正文（品牌简介、套餐结构与价格分析、使用需求分析、优势与限制、上手建议），按页面正文统计 1702–2004 个汉字（灵动云 2004、暮光加速 1883、微风网络 1702、飞猫云 1998、FLYV 1982、浪网 1927、隐形人 1905），独立的 SEO Title、Description、H1、要点、页面可见的常见问题（同时输出 FAQPage）、BlogPosting、真实的发布 / 更新日期和修改记录、读者能看懂的资料来源说明。
- 每篇都经过独立的事实核对（品牌数据、套餐数据、原始资料逐项比对，派生数字重算），再由跨品牌复核去掉句式雷同的段落。
- 其余 12 个品牌页的 Title / Description 改为按各自线路、地区数与流量范围生成，修正了英文名粘连与重复。

**结构化数据与内链**

- 文章与品牌页改用 BlogPosting（headline 等于 H1，日期等于页面可见日期）；首页、品牌库、全部文章（含分页）与五个栏目列表页使用 ItemList（灵动云专区页与 noindex 的标签页没有加）；去掉无用的 SearchAction；文章常见问题改为在页面上可见。
- 现有 16 篇文章补充 133 条正文内链，合并重复的常见问题小节，为长标题补充较短的 seoTitle；六个上榜品牌资料页的“相关阅读”按品牌挑选（其余 12 个品牌资料页仍共用同一组 4 篇通用文章）；泛化锚文本（“查看”“品牌专区”）改为写明目标；文章卡片去掉空锚文本的图片链接。
- 标签页、搜索页改为 noindex, follow；robots.txt 不再禁止 /search/。

**新增 8 篇专题文章**（每篇一个主要意图，与已有文章不重复，均经独立核对）

- Clash Meta 订阅兼容、多设备共用、AI 工具节点选择、YouTube 4K 与 Netflix 网速流量（2026-11-16）
- IEPL 与 IPLC 区别、晚高峰变慢自测、七家低价套餐价格对比、流量倍率（2026-11-24）
- 文中引用的官方数字（YouTube、Netflix 建议网速与流量，OpenAI、Anthropic、Gemini 支持地区，Clash 项目说明）在 2026-11-24 由网页抓取逐项复核，内容一致。

**事实更正**

- 灵动云测评不再把三份记录合并成“共同点”，改为逐份说明；节点地区文章的 AI 建议改为按出口判定；灵动云 11-01 检测记录里“美国04 TikTok 为 JP”的转录错误已按截图更正为 US；“2026 机场怎么选”的标题去掉“不会后悔”这类承诺式说法。
- 品牌数据补记资料内部的矛盾（微风网络御风年付、飞猫云宇宙版年付与折扣比例不符，这两项价格 2026-11-25 已由站长核对无误，见第 12 节；飞猫云线路写法前后不一，暮光加速宣传文案与原稿的客户端说法不同等），灵动云与 FLYV 的优惠码适用范围、灵动云订阅申请条件按原稿改正，流量包不再继承周期套餐的设备说明。

- 测试记录的说明全站统一为“注明日期与出口节点，网络环境、工具与方法写到资料能提供的程度，缺的项标‘未注明’”（首屏、页脚、关于页、灵动云专区、节点实测与机场测评栏目等）；关于页补充“转录错误的更正除外，更正写进修改记录”。

**抓取、IndexNow 与部署**

- sitemap、站内搜索与 IndexNow 共用一套“最后修改日期”规则：随文章、品牌正文、品牌数据、套餐数据、更新记录与推荐榜调整日期计算。
- IndexNow 脚本：`--urls` 只接受 sitemap 中的规范 URL 并记录 sitemap 的 lastmod；自动发现已从 sitemap 移除且线上返回 404 / 410 / 301 / 308 的地址并通知（301 时同时提交新地址）；只提交线上返回 200 的页面；所有失败（sitemap 读取、密钥验证、网络错误、HTTP 失败、Retry-After）都写日志；缺参数时直接报错。
- Node 部署时，带结尾斜杠的 www 地址与文件一跳 301 到主域名并保留路径和参数（不带斜杠的 www 地址仍是两跳，见第 10 节）；`_headers` 覆盖 pages.dev 分支别名；预览环境的 robots 改为允许抓取（靠 noindex 生效），`site-check --expect-preview` 同步按新规则检查；DEPLOY.md 写明 Cloudflare 上 HTTPS、www、Bingbot 放行与静态导出验证的步骤。
- `scripts/write-indexnow-key.mjs` 原来会删除 `public/` 下所有 8 位以上文件名的 .txt（包括站长以后可能放的 `security.txt`），现在只删除内容等于文件名的旧密钥文件。

**可信度页面**

- 测评方法页新增“推荐榜排序原则”，并定义“资料已核对”（与资料原文逐项核对，不等于在结算页下单验证）和“原稿参考价”（2026-11-25 全部品牌价格经站长核对后，页面不再使用这两个标签，统一标为“价格已核对”，见第 12 节）；披露页新增“首页推荐榜与上榜品牌”；关于页补充维护者、作者与利益关系说明；新增 /updates/ 更新记录；联系页在未设置邮箱时不再显示环境变量名、不承诺回复时限；隐私页说明推广链接的邀请码与搜索词的去向，未设置邮箱时不再请读者“通过联系页联系我们”。
- 全站“不打分、不排名”说法统一为“不打分；首页推荐榜是含推广合作因素的编辑推荐顺序，不是测评结论”。

**性能与可访问性**

- 套餐筛选组件不再把 zod 与数据打进浏览器脚本；完整套餐只在读者点“显示全部”或改筛选时追加，不再整表替换；筛选计算降为低优先级。
- 推广卡片按钮对比度修复；推广按钮带“推广”小标签；“站长实测”徽章不再使用表示“已核对”的绿色勾选；页脚与目录的非内容标题不再用 H2。
- 去掉所有延迟渲染（content-visibility）样式：页内锚点落点、标题进入无障碍树、卡片阴影都恢复正常。
- /compare/ 单独成页（URL 不变），套餐筛选组件的脚本只由 /compare/ 引用，其他栏目页和文章页首次加载时不再下载（桌面端页眉的“套餐比较”链接进入视口后，Next.js 仍会在页面加载完成后空闲预取它，约 4 KB）；点“显示全部”后键盘焦点移到表格，不再丢失。
- 深蓝渐变区域的键盘焦点框改为白色；常见问题收起后对读屏隐藏，不再把每个答案标成地标（答案文字仍在 HTML 中，FAQPage 与页面一致）；资料档案区块改由自己的 H2 命名；首页概览每项标签只读一次。
- 手机上价格单位不再断行；首页低价对比按钮文字缩短为“七家机场低价套餐价格对比”，360px 宽度放得下。

## 7. IndexNow 的配置与验证结果

**配置**

- 密钥：从环境变量 `INDEXNOW_KEY` 读取（目前**未设置**）。设置后，构建前的 `scripts/write-indexnow-key.mjs` 会生成 `public/<key>.txt`，部署后应能通过 `https://jichangxuan.blog/<key>.txt` 访问。
- 提交脚本：`scripts/indexnow.mjs`，只能手动运行，不随构建或页面访问触发。检查规则：
  - 默认、`--all` 与 `--urls` 模式先读取 sitemap，读不到就整次退出；`--urls` 指定的地址必须在 sitemap 里，否则整次拒绝；`--removed` 模式不读 sitemap，要求地址线上返回 404 / 410 / 301 / 308，否则整次拒绝。
  - 所有目标必须属于本站域名，否则整次拒绝。
  - 普通地址逐个检查线上是否返回 200：不是 200 的地址本次跳过、不记录，其余地址照常提交。
  - 提交前确认密钥文件在线可访问且内容等于密钥，否则整次不提交。
- 记录：`.indexnow/state.json` 保存每个 URL 上次成功提交时的 sitemap lastmod；`.indexnow/log.jsonl` 记录正式运行（非干运行）中的每批提交结果，以及 sitemap 读取、地址校验、密钥验证、网络错误、HTTP 失败与 Retry-After 等失败。干运行、未设置密钥直接退出、没有需要提交的地址这三种情况不写日志。
- 常用命令：`npm run indexnow:dry`（只列出将提交的地址）、`npm run indexnow -- --all`（首次上线）、`npm run indexnow`（之后每次部署后增量提交）。

**2026-11-24 验证结果（未提交任何 URL）**

- DNS：`jichangxuan.blog` 已托管在 Cloudflare（NS：coby.ns.cloudflare.com、nelci.ns.cloudflare.com），但没有 A / AAAA 记录；`www.jichangxuan.blog` 不存在（NXDOMAIN）。网站没有上线。
- `npm run indexnow:dry`：提示未设置 `INDEXNOW_KEY`，随后因无法读取 https://jichangxuan.blog/sitemap.xml 退出（退出码 1）；干运行模式没有写入 `.indexnow/` 任何文件。
- 本地 sitemap 试运行的结果见第 10 节。
- 结论：IndexNow **没有提交，也没有被 Bing 验证**。上线后按第 8 节第 4 步执行。
