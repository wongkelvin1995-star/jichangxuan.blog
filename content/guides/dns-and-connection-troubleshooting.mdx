“已连接”只表示客户端和节点握手成功，不代表网页一定能打开。中间还有代理模式、DNS、本地网络、其他软件四五层可能出错的地方。这篇按一个固定顺序排查，大多数问题在前三步就会解决，剩下的也能定位到该找谁。

## 第 1 步：换节点

先换 2–3 个不同地区的节点。如果换完就好了，说明是单个节点故障，不用再查别的。

顺便看一眼客户端的“日志”：

| 日志里出现 | 通常意味着 |
| --- | --- |
| timeout / i/o timeout | 节点没有回应：维护中、端口被封、本地网络不稳定 |
| connection refused | 对方拒绝：端口或地址错误、节点已更换、订阅过期 |
| tls handshake failed | TLS 握手失败：系统时间不准、证书问题、中间设备干扰 |
| dns resolve failed | 解析节点域名失败：本地 DNS 被污染或断网 |

## 第 2 步：查流量与订阅

登录机场官网用户中心，确认：

- 套餐没有到期；
- 本月流量没有用完（用完后多数机场会让所有节点“看起来正常”但实际不通）；
- 订阅链接没有被重置（有些机场允许用户重置订阅，旧链接随即失效）。

订阅链接类用户同时在客户端里“更新订阅”一次，确保节点列表是最新的。

## 第 3 步：确认代理模式

**系统代理有没有开？** Windows 看“设置 → 网络和 Internet → 代理”，macOS 看网络偏好的代理标签。客户端里的开关可能被意外关闭。系统代理怎么开、退出客户端前为什么要先关，见[Windows 客户端教程](/guides/windows-client-setup/)。

**规则模式下目标被判为直连？** 临时切到全局模式再试。全局能打开、规则打不开，说明规则没把这个域名分到代理，到“连接”页面看它匹配了哪条规则，调整对应代理组的策略。

**应用不读系统代理？** 游戏、命令行工具常见。换 TUN 模式，详见[TUN 模式与系统代理有什么区别](/guides/tun-vs-system-proxy/)。

## 第 4 步：DNS

到这一步，症状通常是“部分网站打不开”“能打开 IP 打不开域名”“网页打开一半卡住”。

### 判断

切换全局模式，用浏览器访问一个纯 IP 地址的网页（例如 1.1.1.1）。能打开但域名打不开，就是 DNS。

### 处理顺序

1. **让客户端接管 DNS。** Clash 系客户端开启 TUN 后默认用 fake-ip 处理 DNS，绝大多数污染问题随之消失；只用系统代理时，浏览器通过代理解析，一般也没问题，除非浏览器自己开了“安全 DNS”且指向了不可达的服务器。
2. **刷新本地 DNS 缓存。** Windows 运行 `ipconfig /flushdns`；macOS 执行 `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`。
3. **检查浏览器的安全 DNS 设置。** Chrome / Edge 的“使用安全 DNS”若指向某个被封锁的 DoH 服务器，浏览器会自己解析失败。改为“使用当前服务提供商”或关闭，让代理处理。
4. **Android 私人 DNS。** 设为“自动”或关闭，避免与客户端冲突，设置位置见[Android 客户端教程](/guides/android-client-setup/)。
5. **路由器 DNS。** 部分路由器或运营商会劫持 DNS 查询。把电脑网卡的 DNS 临时改为 223.5.5.5 或 119.29.29.29 之类的公共 DNS，看是否有变化；注意这只影响直连流量的解析。
6. **客户端 DNS 设置被改过。** 如果你之前照着某个教程改过 DNS 配置，恢复默认再试。

## 第 5 步：本地网络

- 关闭代理，看宽带本身是否正常；宽带都不稳，代理当然不稳。
- 换一个网络（手机热点与宽带互换）测试。热点正常、宽带不正常，通常是运营商线路对该机场节点不友好，或者晚高峰拥挤；晚高峰连续自测的方法见[机场晚高峰变慢怎么办](/speedtest/peak-hour-stability-guide/)。
- 公司、学校、酒店网络可能封锁常见代理端口，表现为所有节点超时。

## 第 6 步：软件冲突

- 同时运行两个代理 / VPN 软件：只保留一个。手机上同一时间也只能有一个 VPN 类应用处于连接状态，iPhone 在“设置 → VPN”里能看到当前是哪一个，见[iOS 客户端教程](/guides/ios-client-setup/)。
- 安全软件、防火墙：临时关闭测试；确认是它拦截后，把客户端加入信任。
- 浏览器代理扩展（例如旧的 SwitchyOmega 配置）：扩展会覆盖系统代理设置，先禁用。
- 游戏加速器：很多加速器也是 TUN 方式工作，与客户端冲突。

## 第 7 步：协议与系统时间

- **协议支持**：旧版 Clash 内核不支持 VLESS、Hysteria2 等新协议，节点会显示为不可用或导入时报错。换用 Mihomo 内核的客户端，例如 Clash Verge Rev，用法见[Clash Verge Rev 使用教程](/guides/clash-verge-rev-guide/)。
- **系统时间**：TLS 握手要求时间大致准确。电脑时间差了几分钟以上，所有 TLS 类节点都会握手失败。打开系统的“自动设置时间”。

## 还不行：怎么找客服

把以下信息一起发给机场客服，能省掉来回几轮问答：

- 使用的客户端与版本；
- 出问题的节点名称、发生时间（精确到分钟）；
- 你的运营商与大致城市；
- 日志里的错误行（去掉订阅链接和账号信息后截图）；
- 你已经做过的排查步骤。

以[灵动云](/lingdongyun/)为例，资料显示其客服可以协助处理安装、节点切换、DNS、TUN 与 iOS 客户端相关问题，渠道有 Crisp 在线客服与工单。

## 一张速查表

| 症状 | 最可能的原因 | 先做什么 |
| --- | --- | --- |
| 所有节点超时，换网络正常 | 当前网络封锁端口或线路拥堵 | 换节点地区，晚高峰避开 |
| 所有节点超时，换网络也不行 | 订阅过期 / 流量用完 / 系统时间错误 | 查用户中心，校准时间 |
| 浏览器正常，其他软件不走 | 应用不读系统代理 | 开 TUN |
| 部分网站打不开 | DNS 污染或浏览器安全 DNS 设置 | 第 4 步 |
| 关掉客户端后断网 | 系统代理残留 | 关闭系统代理设置 |
| 连接一会儿就断（手机） | 后台被杀 | 关闭电池优化、允许后台 |
