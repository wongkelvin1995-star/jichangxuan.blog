白天用着顺畅，到了晚上八九点网页变慢、视频转圈，是用机场时很常见的情况。本文讲三件事：晚高峰为什么会变慢，怎么用固定的方法自己测，测完怎么读结果、接下来做什么。中间附一份可以直接复制的记录模板。

本文不对任何品牌的晚高峰表现排名或下结论。本站只有灵动云有测试记录，而且还没有本站自己的晚高峰实测；其余品牌本站暂无测试记录。

## 晚高峰为什么会变慢

本文说的晚高峰指 20:00–23:00，也是多家品牌资料建议重点试用的时段。变慢的原因通常在下面四处，可能同时存在。

### 运营商的跨境出口

晚上是家庭上网的高峰。走公网的跨境流量共用运营商的国际出口，流量超过容量就会排队、丢包，表现为延迟升高、速度下降。直连节点，以及跨境段走公网的中转节点，首先受影响。

### 机场的带宽和服务器负载

机场租用的带宽、入口和出口服务器的处理能力都是固定的，同时在线的人越多，每个人分到的越少。卖出去的容量远超实际承载（俗称超售）时，晚高峰尤其明显。这一条和线路类型无关，专线机场同样会遇到。

### 线路类型

专线让跨境段不和公网流量混跑，能避开公网国际出口的拥堵，却避不开机场自身带宽和服务器不够的问题。IPLC、IEPL、BGP 中转、直连各指什么，线路标签为什么证明不了实际走线，见[IEPL 与 IPLC 有什么区别](/speedtest/iepl-vs-iplc/)。

### 你自己这一端

家里的宽带晚上也可能变慢；Wi-Fi 信号被墙体削弱，或者和邻居的网络相互干扰；家人同时在看视频、下载更新、同步网盘。这些都容易被误认为是机场的问题。

## 先花五分钟排除自己这一端

1. 关闭代理，用测速网站测一次本地宽带。本地就慢，先处理宽带或家庭网络。
2. 电脑尽量用网线；只能用 Wi-Fi 时靠近路由器，优先连 5 GHz。
3. 暂停家里其他设备的大流量任务，再测一次。

如果不是变慢，而是完全连不上、网页打不开，那属于连接故障，按[DNS 与连接故障排查](/guides/dns-and-connection-troubleshooting/)的顺序处理。

## 一套可以连续几天重复的自测方法

[测评方法](/methodology/)页列出了本站推荐的自测步骤，这里把它展开成一个连续几天的计划。

<Callout type="tip" title="核心原则">
只让时间变化：设备、网络、客户端、节点和测速工具全部固定，连续测几天再下结论。
</Callout>

### 固定条件

| 条件 | 怎么固定 |
| --- | --- |
| 设备与接入 | 同一台设备，同一种接入方式（网线，或同一个 Wi-Fi 频段） |
| 客户端 | 同一个客户端和版本，同一种代理模式 |
| 节点 | 1 个主用节点，加 1–2 个其他地区的备选，每次都测这几个 |
| 工具 | 同一个测速页面，尽量选同一个测速服务器 |

### 固定时点

- 白天对照：每天在非高峰时段测一次，例如上午或下午。
- 晚高峰：在 20:00–23:00 内取三个固定时点，例如 20:30、21:30、22:30。
- 连续 3–5 天，尽量包含一个周末晚上。

### 每次按同样的顺序测

1. **本地宽带**：关闭代理测一次，记下载速度。
2. **客户端延迟**：用客户端自带的延迟测试，记目标节点的数值，超时就写超时，顺便看看同地区其他节点。
3. **吞吐测速**：连上目标节点，用 IPCheck.ing 一类测速页测下载、上传、延迟和抖动。
4. **实际使用**：打开 YouTube 播放一段视频，在“详细统计信息”里看连接速度和丢帧，或者打开你平时常用的服务。
5. **当场记录**：测完立刻填表，不靠回忆。

本站已有的记录用过这几类工具：2026-11-01 的检测用 MiaoKo，只测延迟和服务地区标签，没有测速；2026-11-10 的实测用了 IPCheck.ing、客户端“测试延迟”和 YouTube 统计信息。工具不同，读数含义就不同，一轮自测里不要中途换工具。

### 延迟测试和测速不是一回事

| 指标 | 能回答 | 不能回答 |
| --- | --- | --- |
| 客户端延迟测试 | 节点连不连得上、响应快不快、有没有超时 | 带宽够不够 |
| 下载、上传测速 | 短时间内能跑多快 | 长时间播放稳不稳 |
| 抖动 | 延迟波动多大，影响通话和游戏 | 网页、下载快不快 |
| 视频播放统计 | 实际播放时的连接速度和丢帧 | 其他服务的情况 |

晚上带宽被占满时，延迟可能变化不大，下载速度却明显下降；反过来，下载快也不代表稳，抖动大的时候，视频通话和游戏照样会卡。所以每次都要把这几项一起记下来，不能只看一个数字。

## 记录模板

把下面这段复制到笔记软件或表格里。前面的环境部分整轮只填一次，表格每测一次填一行。

```
晚高峰自测记录
运营商 / 城市：
接入方式：网线 / Wi-Fi（2.4 GHz 或 5 GHz）
设备与系统：
客户端与版本、代理模式：
测试节点：主用 ____；备选 ____
测速页面与测速服务器：

| 日期 | 时点 | 本地宽带下载 Mbps | 节点 | 客户端延迟 ms | 下载 Mbps | 上传 Mbps | 抖动 ms | 视频（清晰度 / 缓冲 / 丢帧） | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  | 白天对照 |  |  |  |  |  |  |  |  |
|  | 20:30 |  |  |  |  |  |  |  |  |
|  | 21:30 |  |  |  |  |  |  |  |  |
|  | 22:30 |  |  |  |  |  |  |  |  |
```

填写时注意三点：

- 时点精确到分钟，跨天比较时只比同一时点。
- 超时就写“超时”，不要留空。
- 备注写家里同时在用的设备和临时改过的设置，排查时用得上。

## 怎么读结果

先看几天里的大致范围和有没有超时，不要只盯某一次的最高值。

| 你看到的现象 | 更可能的原因 | 下一步 |
| --- | --- | --- |
| 关闭代理时本地宽带也明显变慢 | 宽带或家庭网络 | 先处理本地：换网线、减少同时使用的设备、问宽带运营商 |
| 本地正常，所有节点、所有地区一起变慢 | 机场整体负载、入口拥堵，或你的运营商到入口的线路 | 换网络（例如手机流量）对比，记录几天后找客服 |
| 只有某个节点或地区变慢 | 该节点负载，或该地区的跨境段、出口 | 换同地区其他节点，或换地区 |
| 延迟正常，下载明显下降 | 带宽被占满 | 换节点，大文件下载挪到白天 |
| 延迟和抖动飙升、偶尔超时 | 路径拥堵或丢包 | 换地区；客户端支持时换协议对比 |
| 测速正常，只有某个网站或视频慢 | 目标服务自身，或分流规则 | 换出口地区，检查规则 |

## 不同条件的记录不能直接比

灵动云有两份带速度数据的记录：一份在晚上（2026-10-28，品牌资料附带的文字记录，不是本站测试），一份在上午（2026-11-10 站长实测）。本站与灵动云存在推广合作。看起来正好能回答“晚高峰慢多少”，其实不能。

| 项目 | 2026-10-28 文字记录 | 2026-11-10 站长实测 |
| --- | --- | --- |
| 时间 | 21:26–21:45（晚高峰） | 10:54（上午） |
| 本地网络 | 中国联通，城市未注明 | 运营商与城市均未注明 |
| 节点 | 香港、新加坡、美国 | 日本5 |
| 套餐 | 资料未写明 | 穿云（资料称 IPLC 专线） |
| 工具 | 未注明 | IPCheck.ing |
| 证据 | 资料提供方的文字记录，无截图 | 站长整理的报告图，原始截图未附 |
| 下载 | 香港 10.8、新加坡 13.2、美国 7.07 Mbps | 191.43 Mbps |
| 上传 | 香港 16、新加坡 18.7、美国 9.06 Mbps | 2.17 Mbps |
| 延迟 | 香港 84、新加坡 64、美国 101 ms | 107.85 ms |
| 抖动 | 香港 6、新加坡 18、美国 23 ms | 121.6 ms |

只看数字会得出矛盾的结论：晚上的下载低得多，上传、延迟和抖动的数字却比上午好看。原因是两份记录除了时间，网络、节点、套餐、工具和证据类型全都不同，差异没法归到“晚高峰”头上。两份放在一起，最多说明结果可能波动很大。

各自的局限也要一起看：10-28 是单次文字记录，记录方的结论是“适合网页、AI 与 720p 视频，不适合 1080p 以上或大文件下载”；11-10 是单次上午测试，不代表晚高峰。另一份 2026-11-01 的检测（见[灵动云 60 个节点解锁检测记录](/speedtest/lingdongyun-2026-11-01-node-unlock-check/)）在 19:12，早于通常的晚高峰，也没有测速项。完整内容见[灵动云测评](/reviews/lingdongyun-review-2026/)和[灵动云日本5 节点实测报告](/speedtest/lingdongyun-2026-11-10-japan-node-report/)。

这正是自测要固定条件的原因：除了时间什么都不变，结果才能比。

## 测完之后怎么做

1. **换节点**：先在同地区里换延迟低、没有超时的节点。
2. **换地区**：香港拥挤时试台湾、日本、新加坡；要用特定地区的服务时注意出口地区，取舍见[机场节点地区怎么选](/speedtest/node-regions-explained/)。
3. **换协议或模式**：客户端提供不同协议或线路的节点时，换一个对比；只有官方客户端的，看设置里有没有相关选项，或者问客服。
4. **调整用法**：高峰期把视频清晰度调低一档，大文件下载和系统更新放到白天。
5. **带着记录找客服**：附上连续几天的记录表、运营商和城市、节点名和本地宽带对照；还要准备哪些信息，见[DNS 与连接故障排查](/guides/dns-and-connection-troubleshooting/)里“还不行：怎么找客服”一节。
6. **先别换长周期**：在你常用的时段连续几天都达不到需要，就别急着买长周期；各品牌的退款渠道，见[机场品牌资料库](/brands/)里对应的品牌页。
